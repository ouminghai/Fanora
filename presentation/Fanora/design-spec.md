# Fanora 展示文稿 · 三方向共同设计 Spec

本项目是一套面向黑客松评委、产品评审与技术评审的 16 页正文加 4 页附录展示文稿，演讲时长约 8–10 分钟，其中现场产品演示约 3 分钟。观众通常在较远距离观看，因此页面必须以结论式标题、真实产品截图和单一视觉主角为核心，不把题纲全文搬上屏幕。最重要的传播目标，是让评委在结束后仍能复述 Fanora 的完整价值闭环：粉丝的签到、任务、互动与创作不再散落，而是沉淀为 FAN 与长期会员身份；AI Agent 通过多轮状态持续理解真实故事，将其共创为可迭代的数字纪念作品；Memory Forge 用五维分析、模式选择与确定性规则管理发行风险；最终由 IPFS 和 Monad 保存作品与验证归属，再通过 Gallery 与社区互动回到下一轮成长。

目标受众既关心产品情感价值，也会追问 Agent 工作流、AI 与确定性服务边界、Forge 是否可审计、链上与站内职责如何划分。因此 Deck 的情绪线不能只“浪漫”，也不能退化成纯架构汇报。前半段要从粉丝热爱与记忆损失切入，建立“为什么值得做”；中段通过真实 UI 展示身份成长、持续对话与发行策略，证明“产品已经可用”；后半段用清晰架构和链上分工回答“为什么可信、如何恢复”；最后回到“我为何热爱”的人文收束。页面标题必须优先使用题纲里的完整观点句，每页只保留 1 个主结论、3–5 个辅助信息和 1 个视觉主角。

输出采用 16:9、1920×1080 的 HTML Deck。最终完整版本默认使用多文件架构：每页独立 HTML，配套概览墙与 PDF；当前三方向初稿每个方向先制作两页代表稿，统一选择第 1 页封面与第 6 页 AI NFT Studio 内容页，以同时检验品牌第一印象、长标题排版、真实 UI 截图承载能力和产品/技术信息密度。正文最小 28px，标题 64–120px，Hero 标语可达 150–210px。Fanora 与 Monad Logo 必须使用真实仓库资产，AI Studio 使用 `docs/image3.png` 的真实截图；禁止使用通用 Web3 图标堆砌、投机型金融符号、编造数据与低质量 SVG 场景插画。

图片判断：内容必需。Fanora 是数字产品，真实 UI 本身就是说服力核心；去掉截图会直接损害“已经实现”和“持续对话”的信息，因此三版必须共享同一套 Logo 与 UI 资产，只改变设计诠释。视觉母题来自产品独有的“记忆被连接、身份被积累、作品被永久保存”：可表现为记忆轨道、身份档案、舞台光束、状态节点或作品框，但不能沦为无意义装饰。三方向的结构必须明显不同：A 以人文档案与圆角画框组织；B 以发布会大字与舞台屏幕组织；C 以品牌化轨道与非对称构图组织。

## Form 推导五问

- 叙事角色：封面是品牌承诺与情绪入口；AI Studio 页是产品证据与关键差异页。
- 观众距离：约 5–10 米投屏，优先大字、短句、截图局部高可读性。
- 视觉温度：封面应有情感张力；产品页在温暖与技术可信之间保持平衡。
- 容量估算：封面仅保留品牌、标语、说明与网络信息；产品页保留一句核心观点、三条差异和一个主截图。
- 视觉母题：Fanora 独有的“记忆轨道 / 身份档案 / 舞台光”，form 必须从这一闭环生长。
