# Fanora 用户洞察与商业逻辑

> **Hackathon MVP 产品共识与验证框架**
>
> **核心定位：** Fanora 连接粉丝贡献、FAN 奖励、AI 辅助创作、链上作品与会员权益，形成一条完整但可控的粉丝成长闭环。

## 1. 文档目的

本文件用于统一团队对用户、需求、商业逻辑和 Hackathon MVP 的理解，并作为产品设计、Demo 验收与 Pitch 叙事的共同依据。

本文刻意区分“访谈观察”“团队推论”和“待验证假设”，避免把少量访谈反馈直接写成普遍事实。

| 信息层级 | 定义 | 本文件中的使用方式 |
| --- | --- | --- |
| 访谈观察 | 用户明确表达的行为、偏好或困难 | 作为问题发现的证据，不直接外推市场规模 |
| 团队推论 | 基于访谈与竞品观察形成的产品判断 | 用于设计 MVP，但需要通过使用数据继续检验 |
| 待验证假设 | 尚未获得充分证据的商业或行为假设 | 转化为测试问题和验收指标 |

## 2. 用户研究背景

当前用户洞察主要来自团队成员对长期追星用户、高消费粉丝及深度创作者的非结构化访谈，以及对韩国打投平台、官方 Fan Club 和现有 Fanora Demo 的观察。

- 访谈样本目前较小，适合用于发现问题和收敛 MVP，不适合用于宣称行业普遍比例。
- 不同地区粉丝生态差异明显：国内更偏移动端与社交平台，海外官方 Fan Club 和网页会员体系更成熟。
- 真人艺人素材、会员权益和票务能力都依赖官方授权或合作，Hackathon 只能进行概念验证。

## 3. 核心用户洞察

| 访谈观察 | 产品含义 | MVP 对应 |
| --- | --- | --- |
| 普通粉丝真正愿意付费的是可感知权益，而不是 NFT 本身。 | Badge 与 FAN 必须对应会员身份、限定内容或未来权益。 | 展示一个 Badge/FAN 可解锁的模拟权益。 |
| 真正持续创作的通常是少数深度粉、同人创作者、CP 粉和应援站。 | AI 创作不需要面向所有粉丝；普通粉丝可以浏览、收藏和消费。 | AI Studio 服务创作者，Gallery 服务普通粉丝。 |
| 不会设计、不会写复杂 Prompt 会阻碍有想法的粉丝完成作品。 | AI 的价值是理解自然语言、组织 Brief、调用素材与辅助修改。 | 展示 Brief、生成和一次自然语言修改。 |
| 现有社区、打投、会员、周边和创作工具彼此分散。 | Fanora 的价值不是替代所有平台，而是连接贡献、身份、创作与权益。 | Demo 展示贡献到作品的连续路径。 |
| 国内追星用户更偏手机端。 | 核心流程必须 Mobile First，即使比赛用桌面 Web 演示。 | 桌面工作台＋手机端分步流程。 |

## 4. 粉丝分层与对应价值

| 粉丝类型 | 主要需求 | Fanora 对应能力 |
| --- | --- | --- |
| 普通粉丝 | 内容、社区、身份与会员权益 | Community、Gallery、会员身份与权益展示 |
| 活跃粉丝 | 任务、FAN、等级和贡献记录 | Quests、FAN 流水、终身累计 FAN、Badge |
| 核心粉丝 | 限定内容、周边、活动与优先资格 | 高等级 Badge、权益门槛和会员凭证 |
| 粉丝创作者 | 创作工具、素材边界、展示与收益机会 | AI Studio、素材包、ERC-1155 发布、Gallery |

> **关键判断：** Fanora 不要求所有粉丝都创作。少数创作者负责产出，大多数粉丝负责参与、收藏和消费；会员权益负责吸引与留存。

## 5. 用户问题

市场上已经存在社区、任务、积分、投票、会员、周边商城和 AI 创作工具。问题不是没有工具，而是这些服务无法共同识别同一个粉丝。

- 粉丝在不同平台反复注册和重新积累身份。
- 长期贡献被锁在各个平台的私有数据库中。
- 普通粉丝得到积分，却缺乏明确且即时的消耗场景。
- 深度粉丝有创作想法，但缺乏设计能力、素材边界和发布工具。
- 艺人方难以统一识别核心粉丝和有价值的粉丝创作者。

## 6. Fanora 的解决方案

> **一句话产品：** Fanora 是一个 AI 驱动的链上粉丝社区：粉丝通过贡献获得 FAN 和身份成长，创作者使用 AI Agent 制作周边，作品发布到 Monad 并由社区收藏。

产品闭环：

1. 加入社区并建立会员身份
2. 签到、发帖或完成任务，获得 FAN 与等级积累
3. 有创作意愿的粉丝消耗 FAN 使用 AI Studio
4. Agent 组织创作 Brief、生成作品并支持一次修改
5. 用户确认后将作品固定到 IPFS，并发布为 Monad ERC-1155
6. 其他粉丝在 Gallery 收藏或购买，创作者积累作品与社区声誉
7. Badge 与 FAN 在未来连接会员内容、周边与活动权益

## 7. AI 与 Web3 的职责分工

| AI 负责 | 业务系统负责 | Monad / IPFS 负责 |
| --- | --- | --- |
| 理解用户需求与粉丝语境 | 用户、任务、FAN、等级和业务状态 | ERC-721 SBT 会员身份 |
| 整理创作 Brief | FAN 扣费、失败处理和幂等 | ERC-1155 作品所有权 |
| 编排 Prompt 和调用素材包 | 发布资格、发行量与价格校验 | 链上交易与 Token ID |
| 生成图片、名称、描述和属性 | Gallery、收藏与市场业务事实 | 图片与 Metadata 内容地址 |
| 内容与质量检查、保存草稿 | IPFS 上传与链上发布服务编排 | 公开可验证的归属记录 |

团队统一口径：AI 负责理解和创造；业务系统负责确定性规则；Web3 负责会员身份和作品所有权的可验证记录。

重要边界：根据当前架构，FAN、任务和等级明细保存在 PostgreSQL；不要在 Pitch 中声称 FAN 已经是用户钱包中的链上 Token。

## 8. 商业逻辑

| 参与方 | 获得的价值 | 可能的付费／收益方式 |
| --- | --- | --- |
| 普通粉丝 | 社区内容、身份成长、收藏与会员权益 | 会员费、作品收藏、限定周边 |
| 粉丝创作者 | AI 创作工具、合法素材边界、展示和收益机会 | 使用 FAN 创作；获得收藏或销售收益 |
| 艺人／经纪公司 | 会员收入、核心粉丝识别、社区活跃和创意反馈 | SaaS、会员分成、创作与交易服务费 |
| Fanora | 提供社区、AI、身份、资产和权益基础设施 | 平台服务费、AI 使用费、交易与企业服务费 |

## 9. Hackathon MVP

Hackathon 只验证一条最小、可演示的 AI 共创闭环：

> **唯一 Happy Path：** 用户选择素材包和视觉风格，通过 Agent 形成创作 Brief，生成并修改一次作品，确认后发布到 Monad，并在 Gallery 中看到作品。

### 必须真实或至少真实跑通过一次

- AI 根据创作需求输出结构化 Brief
- AI 生成图片、名称、描述和属性
- 用户通过自然语言完成一次修改
- 生成结果进入发布确认页，无需重复上传或填写
- 作品上传 IPFS 并发布为 Monad ERC-1155
- Gallery 与区块浏览器显示同一个真实作品

### 可以预置或模拟

- 历史社区内容、已完成任务和测试账号初始 FAN
- 一个固定素材包与三种视觉风格
- 会员权益展示与外部合作页面
- AI 或 RPC 不稳定时的缓存结果与录屏加速

### 本轮不做

多社区、多 Creator、多 Agent、真实票务、完整素材后台、二级市场、拍卖、复杂稀有度、跨链身份、DAO、主网部署和生产级治理。

## 10. MVP 成功标准

| 维度 | 验收标准 |
| --- | --- |
| 可理解 | 未参与开发的人能说清 FAN 来源、AI 价值与 Monad 结果。 |
| 可完成 | 测试用户无需开发者指导即可走完生成、修改和发布。 |
| 可验证 | 区块浏览器可打开，Token ID、合约地址与 Gallery 一致。 |
| 可重复 | 同一测试账号连续三次完成核心 Happy Path。 |
| 可降级 | AI 或 RPC 失败时有明确状态、重试和录屏兜底。 |
| 口径真实 | 真实实现、Mock 和未来规划在 Pitch 中被明确区分。 |

## 11. 当前待验证假设

| 假设 | 如何验证 | MVP 观察信号 |
| --- | --- | --- |
| 深度粉丝愿意使用 AI 辅助创作 | 邀请有创作经历的粉丝完成一次任务 | 是否能完成、是否愿意修改、是否认可输出 |
| FAN 可以连接贡献与创作 | 向用户解释 FAN 来源和消耗后提问 | 用户能否复述、是否觉得规则合理 |
| 普通粉丝愿意收藏 AI 辅助作品 | 展示 Gallery 作品并进行选择访谈 | 收藏意愿、对 AI 标识和授权的关注 |
| Badge 与权益能提升留存 | 展示一个具体权益，而非抽象等级 | 用户是否认为权益值得持续参与 |
| 移动端是国内用户的关键入口 | 用手机完成核心流程测试 | 完成率、输入困难和钱包连接问题 |

## 12. 主要风险与产品边界

| 风险 | 当前处理原则 |
| --- | --- |
| 艺人素材与同人版权 | 没有正式授权时使用自有／许可素材，或明确标注非官方、非商业概念验证。 |
| AI 生成内容争议 | 明确 AI 辅助标识、素材来源、内容审核与禁止生成规则。 |
| Web3 过度承诺 | 强调可验证记录和所有权，不承诺资产永久有价值或现实权益永久履约。 |
| FAN 概念混乱 | 明确 FAN 是平台贡献积分；链上资产是会员 SBT 和 ERC-1155 作品。 |
| 功能范围膨胀 | 所有需求必须对应最终 Demo 镜头，否则进入赛后列表。 |
| 外部服务不稳定 | 准备固定测试账号、缓存草稿、备用 RPC、真实历史交易和预录视频。 |

## 13. 下一步产品工作

1. 冻结 AI Brief、生成、修改和发布四个页面状态及文案。

2. 建立一个固定素材包、一种模板、三种风格和三组标准测试输入。

3. 统一 FAN 费用、首次体验、重新生成与发布费用规则。

4. 将新 AI Studio 接入现有 ERC-1155 发布与 Gallery 链路。

5. 建立 Demo Truth Map：真实实现、预置／Mock、未来规划。

6. 按照同一 Golden Path 每日执行一次产品验收。

7. 核心流程稳定后进行三类用户测试，并据此修改 Pitch。
