# Problem Definition & Mini Demo

## 目标用户是谁？

目标用户是处于早期阶段的 **Web3 创作者、项目社区负责人和社区运营人员**。

他们通常管理几十到几百名社区成员，希望识别真正持续参与和贡献的粉丝，但暂时没有足够的人力或成熟工具建立完整的会员与激励系统。

## 用户遇到了什么具体问题？

粉丝的贡献分散在签到、内容互动、活动参与、社区共创和链上行为等不同场景中。社区运营人员很难快速回答：

- 哪些成员是真正活跃且持续贡献的核心粉丝？
- 一位成员为什么应该获得某个等级或身份？
- 如何用简单、可解释的方式向成员展示其贡献？

目前的判断往往依赖运营人员的个人印象，容易遗漏贡献，也难以形成一致、公平的标准。

## 用户现在如何解决？

- 使用 Excel、Notion 或在线表格手动记录成员行为。
- 通过 Discord、Telegram 或微信群聊天记录观察活跃度。
- 使用平台自带的积分、等级或身份组机器人。
- 由运营人员定期人工评选核心成员并发放奖励。

这些方式可以暂时工作，但数据比较分散，维护成本高，而且结果通常缺少清晰的判断依据。

## 我们准备提供什么帮助？

Fanora 将成员的关键互动数据整理成一份简洁、可解释的粉丝画像，帮助社区运营人员快速了解成员的参与程度、主要贡献和建议身份。

本周只验证一个核心假设：

> 当系统把零散的互动数据转化为清晰的粉丝画像时，社区运营人员能否更快、更有依据地识别核心粉丝？

## Mini Demo 只展示哪个核心功能？

Mini Demo 只展示 **根据一组模拟的社区互动数据生成粉丝画像**。

演示流程：

1. 输入或选择一名模拟成员的数据，包括任务完成数、活跃天数、邀请人数和链上互动次数。
2. 系统生成该成员的粉丝等级、主要贡献摘要和简短的判断理由。
3. 页面以一张 Builder/Fan Profile Card 的形式展示结果。

本周 Demo 的完成标准是：用户能够在 3 分钟内走完整个流程，并理解系统为什么给出该画像。

## 本周明确不做什么？

- 不开发完整的社区管理后台。
- 不接入 Discord、Telegram、X 等真实平台数据。
- 不实现主网部署或真实资产交易。
- 不开发会员付费、NFT 市场和复杂 Tokenomics。
- 不要求用户连接真实钱包或提供敏感信息。
- 不实现自动发放奖励、自动修改积分或自动执行合约交易。
- 不追求完整的 AI Agent 工作流，只使用足以展示核心价值的规则或简单分析能力。
- 不处理大规模用户、复杂权限和生产环境运维问题。

本周的重点不是增加功能，而是通过 Mini Demo 和少量用户反馈，确认“可解释的粉丝画像”是否解决了社区运营人员的真实问题。
