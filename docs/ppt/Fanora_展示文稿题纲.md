### 3. 2 分钟逐字稿

大家好，我们带来的项目是 Fanora，一个 AI Agent 驱动的 Web3 粉丝身份与记忆 NFT 共创平台。

我想先从一个真实消费场景开始。我有一个长期追星的朋友，她每个月都会在会员、周边、应援、活动和内容创作上持续花钱。她也观察到，一些 CP 粉或粉丝周边项目，只要故事、情绪和社群组织到位，销售额和利润空间有机会做到数十万甚至上百万级。所以这不是一个小众爱好，而是一群已经在持续参与、创作和消费的用户。

但问题是，这些贡献大多散落在不同平台：签到、发帖、创作、购买、应援、收藏，最后只变成一条条动态、几张图片，或者一个随时可能丢失的账号。粉丝投入了时间、情感和金钱，却很难形成真正属于自己的长期身份和可验证记忆。

Fanora 想解决这件事。用户通过钱包进入社区，完成签到、任务和互动，获得 FAN 与会员成长；这些经历进入 AI Agent，Agent 会通过多轮对话理解故事、情绪、场景和象征元素，把它创作为专属数字纪念作品；作品再进入 Memory Forge，由五维分析和发行策略决定如何发布。

当作品成功发行后，最终图片和 metadata 会固定到 IPFS，收藏品和持有关系记录在 Monad 上，并展示到 Gallery 和个人 Collection 里。我们不是把所有东西都上链：高频的任务、FAN、Agent 状态留在站内，保证体验顺滑；真正需要长期证明的会员身份、NFT 和归属关系交给 Monad。

所以 Fanora 收藏的不只是一张图，而是“我为什么热爱、我参与过什么、这段关系如何成为我的身份”。我们服务的是一群已经存在的创作者和消费者，让热爱被记录，让身份被认可，让记忆拥有归属。

### 2. Monad 在产品中的职责

Fanora 对 Monad 的表达要清晰：Monad 不是装饰性 Logo，而是承载关键长期证明的网络。

- **网络**：Monad Testnet，Chain ID `10143`。
- **正式会员身份**：ERC-721 不可转让 SBT，证明用户完成正式激活与长期参与。
- **NFT / Badge / 收藏品**：ERC-1155，记录作品、徽章和持有关系。
- **最终作品归属**：图片与 metadata 固定到 IPFS，所有权与收藏关系在 Monad 上验证。
- **链下高频体验**：签到、任务、FAN 余额、Agent 对话状态、Forge Attempt 留在 PostgreSQL / 服务端，确保体验足够快、成本可控。

一句话表达：

**Fanora 把高频互动留在站内，把需要长期保存和证明的身份、作品与归属交给 Monad。**

### 第 2 页｜从一位长期粉丝的每月消费开始

**核心观点**

粉丝经济不是抽象的小众兴趣，而是一群已经持续参与、创作和消费的真实用户。

**场景切入**

一位长期追星用户，每个月可能持续投入在：

- 会员订阅、数字内容和平台权益。
- 周边、专辑、票务、展会和线下活动。
- 应援、打投、二创、图文视频内容和社群组织。
- CP 粉或粉丝周边项目中，热门项目的销售额与利润空间有机会达到数十万甚至上百万级。

**给评委的翻译**

即使评委不了解追星文化，也可以把它理解成一个具备三种特征的市场：

1. **稳定复购**：用户不是偶尔买一次，而是长期围绕关系、作品和身份持续消费。
2. **高强度 UGC**：用户不仅消费，也主动创作、传播、组织活动。
3. **强社区协作**：购买、应援、投票、二创和周边项目常常由社群一起推动。

**收束句**

Fanora 要承接的，正是这类已经存在的情感消费、社区协作和数字收藏需求。

**视觉建议**

- 用一个真实消费账单 / 社群项目 / 周边预售的抽象信息图切入，不要直接假设观众懂“CP 粉”。

**核心观点**

### 第 8 页｜真正的共创，不是一次 Prompt，而是一场持续对话

**核心观点**

LangGraph 将创作拆成可追踪的状态与节点，只有真正需要时才调用图片模型。

**简化流程**

```text
加载视觉模板
→ 理解故事
→ 生成结构化作品草稿
→ 判断是否需要生图
→ 调用受控 Tool
→ 保存新 State 与 Tool Trace
```

**三类生图触发**

1. 用户明确要求“生成图片”。
2. 第二轮仍没有首张预览时，自动尝试生成。
3. 模板、风格、参考图或核心 Prompt 有效变化且作品状态成熟。

**设计价值**

- 避免无意义的重复生图。
- Tool 调用与降级原因可见。
- 图片失败时保留对话、草稿和参考素材，可继续恢复。

**视觉建议**

- 使用一条横向节点流程图。
- 不展示完整 State 字段和全部 LangGraph 节点，把技术细节留到附录。

### 第 9 页｜当作品准备好，Memory Forge 让发行成为高光时刻

**核心观点**

作品生成后，Fanora 通过五维分析和发行策略，让发布不再是一个机械的 Mint 按钮。

**五维分析**

- 原创性：25%
- 视觉质量：20%
- 粉丝情感：25%
- 稀缺性：20%
- 社区潜力：10%

**发行建议**

- 自动建议供应量、FAN 价格和 Forge 模式。
- 用户可以根据建议调整发行策略。
- Stable、Focused、Legendary 三种模式对应不同成本与成功率修正。

**页面金句**

AI 负责理解和建议，确定性规则负责概率、结算与结果。

**视觉建议**

- 以作品预览为中心，周围展示五维评分雷达或五条评分轴。
- 右侧突出“数量 / 价格 / 模式”的发行建议。

### 第 10 页｜即使这次没有上链，故事也不会归零

**核心观点**

Forge 失败代表本次没有进入正式发行，并不意味着故事和作品被抹去。

**页面内容**

- Forge 当前只有“发行成功”与“发行失败”两种结果。
- 失败时保留故事、预览、分析和可调整的发行策略。
- 每次失败增加 1 个 Memory Fragment。
- 5 个 Fragment 可兑换 Stable credit，10 个可兑换 Focused credit。
- 概率、roll、规则版本与结算结果均可记录和审计。

**产品意义**

把失败从资产损失改造成成长反馈，同时保留游戏化参与感。

**视觉建议**

- 使用左右分支：成功进入发行；失败保留作品并获得 Fragment，再回到分析阶段。
- 重点表现“失败可恢复”，避免营造博彩视觉。

### 第 11 页｜只有被确认的记忆，才进入永久保存与链上归属

**核心观点**

Fanora 将创作预览和正式链上资产严格分开，只有成功且通过校验的作品才发布。

**发布链路**

```text
校验本人 SUCCESS Forge Session
→ 规范化作品图片
→ 图片固定到 Pinata IPFS
→ Metadata 固定到 IPFS
→ 创建 ERC-1155 Token Type
→ Mint 创作者首枚
→ Gallery / Collection 展示
```

**页面内容**

- COS 保存社区图片、模板、参考图和 AI 预览。
- IPFS 保存最终 NFT 图片和 metadata。
- Monad ERC-1155 记录 NFT、Badge 与持有关系。
- Gallery 支持点赞、收藏和 FAN 购买；购买链上失败时恢复 FAN。

**视觉建议**

- 用一条从“可变预览”到“不可变资产”的发布管线。
- 清楚标注 COS、IPFS、Monad 三者的职责差异。

### 第 13 页｜让 AI 保持想象力，让资产规则保持确定性

## 七、逐页演讲用语

> 以下内容用于演讲者口头表达，不建议原样全部放到页面上。每页保留一条主线，讲到关键句时适当停顿，让观众有时间理解画面。

### 第 1 页｜开场

大家好，我们带来的项目是 Fanora。

在粉丝文化里，我们常常记得某一次演出、某一首歌、某一个陪伴了很久的人。但这些热爱，大多只停留在一条动态、一张照片，或者一个随时可能消失的账号里。

所以我们想做一件事：**让热爱成为身份，让故事成为作品。**

### 第 2 页｜真实消费场景

在解释 Fanora 之前，我想先讲一个更容易理解的消费场景。

我有一个长期追星的朋友，她每个月都会在会员、周边、应援、活动、演出和内容创作上持续花钱。对她来说，这不是一次性冲动消费，而是一种长期参与。

她也观察到，一些 CP 粉或粉丝周边项目，只要故事、情绪和社群组织到位，销售额和利润空间有机会做到数十万甚至上百万级。

所以我们想让评委先理解一件事：这不是一个小众爱好，而是一群已经在持续参与、创作和消费的用户。

### 第 3 页｜项目介绍

Fanora 是一个连接粉丝、故事与数字收藏的 AI 共创平台。

我们相信，真正值得被收藏的，不只是最后生成的那张图片，而是图片背后的那段经历。每一次参与、互动与陪伴，都应该成为粉丝成长历程的一部分。

Fanora 让 AI Agent 听见这些故事，再把它们创作为专属数字纪念作品，让每一份热爱拥有独特身份、永久记录与可验证的价值。

### 第 4 页｜问题

今天的粉丝并不缺少热情，他们缺少的是一个能够长期承接这份热情的地方。

我们签到、发帖、创作、参加活动，但这些贡献散落在不同平台。平台一换、账号一丢，曾经积累的经历和荣誉也可能随之消失。

**问题不是粉丝没有付出，而是这些付出从未真正属于粉丝自己。**

### 第 5 页｜解决方案

Fanora 做的事情，就是把这些原本分散的瞬间连接起来。

粉丝从社区参与开始，获得 FAN 与会员成长；这些经历进入 AI 共创，变成专属作品；作品经过 Memory Forge，再由 IPFS 与 Monad 完成保存和归属；最后，收藏和社区互动又回到下一轮成长。

它不是一次性的 Mint，而是一条可以持续运转的粉丝旅程。

### 第 6 页｜身份与成长

在 Fanora，身份不是买一张卡得到的，而是通过一次次真实参与积累出来的。

签到、任务和社区贡献会形成 FAN 流水与终身成长。FAN 可以被使用，但已经付出的热爱不会因为消费而被清零，会员等级也不会倒退。

最终，这段成长由不可转让的链上身份承载——它证明的不只是「我拥有」，更是「我曾经参与」。

### 第 7 页｜AI 共创

大多数 AI 创作工具只问一句：「你想生成什么？」

Fanora 的 Agent 会继续问：「这个故事为什么对你重要？你记住的是哪个瞬间？它应该是什么颜色、什么情绪？」

它不是替粉丝随便画一张图，而是和粉丝一起，把一段只有自己懂的记忆，慢慢变成一件只有自己拥有的作品。

### 第 8 页｜Agent 工作流

真正的共创，不能每说一句话就从头开始。

所以我们用 LangGraph 保存 History 与 State，让 Agent 记住用户确认过的故事、风格、模板和参考图。只有用户明确要求、需要首张预览，或者视觉方向真正发生变化时，系统才调用图片模型。

这让创作既有连续性，也避免每一轮对话都重复生成、浪费成本。

### 第 9 页｜Memory Forge

当作品完成之后，我们不希望发布只剩下一个冰冷的 Mint 按钮。

Memory Forge 会从原创性、视觉质量、粉丝情感、稀缺性和社区潜力五个维度理解作品，并给出供应量、价格和模式建议。

于是，发行不再只是技术动作，而成为作品从私人记忆走向公共收藏的高光时刻。

### 第 10 页｜失败与 Fragment

我们也重新设计了失败。

如果本次 Forge 没有成功，故事不会消失，图片不会销毁，用户之前的创作也不会归零。作品会被完整保留，同时获得 Memory Fragment，为下一次尝试积累机会。

**失败不是失去作品，而是这段记忆还在等待更合适的发行时刻。**

### 第 11 页｜上链与收藏

只有成功通过 Forge，并完成归属和版本校验的作品，才会进入正式发布流程。

最终图片与 metadata 被固定到 IPFS，Monad ERC-1155 记录作品与持有关系，创作者获得首枚收藏。之后，作品可以进入 Gallery，被点赞、收藏，也可以使用 FAN 购买。

从这一刻起，它不再只是一个预览，而是一件拥有长期归属的数字纪念作品。

### 第 12 页｜Demo 过渡

接下来，我们不用更多概念解释，而是用三分钟走完一位粉丝的完整旅程。

从连接钱包、完成签到，到向 Agent 讲述故事、生成作品、进入 Forge，再到最终出现在 Gallery 和 Collection 中。

请大家关注的不是某一个页面，而是这些页面如何连接成一条完整的价值链。

### 第 13 页｜AI 与资产边界

Fanora 允许 AI 发挥想象力，但不会把资产安全交给模型的概率输出。

Agent 可以理解故事、推荐模板、优化作品和提出发行建议；但它不能直接扣除 FAN，不能控制 Forge 结果，不能持有私钥，也不能伪造链上成功。

**创作可以开放，资产操作必须确定。** 这是我们整个系统最重要的边界。

### 第 14 页｜系统架构

为了守住这条边界，我们把系统拆成清晰的层次。

前端负责简单顺畅的用户体验，LangGraph 负责智能编排，领域服务负责事务、权限和幂等，适配器负责连接模型、存储与区块链。

这样即使模型超时、图片生成失败或链上交易异常，系统也知道应该停在哪里、保留什么，以及如何恢复。

### 第 15 页｜为什么使用 Monad

我们没有把所有业务都塞到链上。

社区互动、任务和 FAN 是高频行为，留在 PostgreSQL 才能保持简单快速；真正需要长期验证的正式会员身份、NFT 和持有关系，则进入 Monad。

这是我们对 Web3 的理解：不是为了上链而上链，而是把最需要被证明和长期保存的价值交给链。

### 第 16 页｜MVP 完成度

目前，Fanora 已经完成了从钱包登录、社区贡献、FAN 成长、AI 共创、Memory Forge，到 IPFS 与 Monad 铸造、Gallery 收藏的端到端闭环。

我们也主动控制了范围：二级市场、跨链、DAO 和法币支付不是这次 MVP 的重点。

因为在黑客松阶段，我们首先要证明的不是功能数量，而是这条核心路径真的能够走通。

### 第 17 页｜结尾

Fanora 最终想收藏的，从来不只是一张图片。

我们想收藏的是：我为什么喜欢、我陪伴了多久、我参与过什么，以及这段热爱如何成为今天的我。

当贡献能够形成身份，当故事能够成为作品，当记忆能够被长期验证——粉丝拥有的就不再只是一个账号，而是一段真正属于自己的数字旅程。

**Fanora，让热爱成为身份，让故事成为作品。**
