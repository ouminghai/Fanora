# 记录团队决定与 AI 使用情况

> 记录日期：2026-07-23  
> 项目：Fanora Protocol

## 团队做出的重要决定：

1. 将核心问题定为“如何将分散的粉丝互动数据转化为可解释的粉丝画像”。本周 Mini Demo 优先演示输入模拟数据、生成评分与画像卡片的最小闭环。
2. MVP 只运营一个 Fanora 官方社区，用户只有一套全局 FAN、等级、任务和身份，不建设多社区管理体系。
3. 登录方案统一改为 RainbowKit 直连用户自有钱包，通过一次性 challenge 和钱包签名创建会话。Fanora 不生成、导出或保存用户私钥和助记词。
4. PostgreSQL 作为任务、FAN、等级和审核状态的业务事实源，不将频繁变化的积分和完整粉丝画像写入链上。
5. 链上职责拆分为三个合约：Gateway 处理会费，不可转让的 ERC-721 表示唯一会员身份，ERC-1155 表示纪念卡、任务 Badge 和粉丝限量 NFT。
6. 将“可消费 FAN”与“终身累计 FAN”分离，会员等级按终身累计值计算并只升不降，购买或发布 NFT 的消费不会降低已获得的等级。
7. AI Agent 只负责粉丝画像、解释、推荐、内容审核和 NFT metadata 草案；不直接修改 FAN、授予权限、决定会员等级、设定 NFT 价格或供应量，也不持有私钥或直接控制合约。
8. 模型未配置或调用失败时使用可复现的确定性规则降级；Pinata、合约或运营钱包未配置时明确记录为等待配置，不伪造 AI 调用或链上成功。
9. 开发阶段使用 Monad Testnet、测试钱包和最小权限配置，在完成后台重试、对账和权限治理前不进入主网。

- 欧明海（当前唯一已确认成员）：发起人、产品与技术负责人，负责项目方向、需求取舍、全栈开发、测试验证和阶段成果整合。
- 待招募：记录与协作、用户研究 / UI/UX / 运营、Web3 与合约安全成员。截至本次记录，尚未确认其他正式成员。

## 为什么这样决定：

- 可解释的粉丝画像直接对应社区运营者“难以快速、公平地识别核心粉丝”的问题，并且能在 3 分钟内完成演示和用户反馈。
- 单一官方社区和模块化单体架构能减少权限、数据归属和部署复杂度，符合当前人力和 MVP 验证目标。
- 钱包私钥由用户自有钱包保管，可以降低密钥泄露、托管责任和安全合规风险。
- 将高频业务数据留在数据库，只把需要公开验证的会员身份和纪念资产写入链上，能平衡可验证性、成本、隐私与可维护性。
- 将 AI 输出与奖励、权限和链上写入隔离，可以避免不稳定或不可解释的模型结果直接改变用户资产。
- 使用确定性降级和测试网，可以在缺少模型、IPFS 或链上配置时继续演示，同时保持结果真实可追溯。

## 删除或暂时不做的功能：

- 已删除 Web3Auth、Identity Token 校验、嵌入式钱包和私钥导出功能，统一改用 RainbowKit 直连钱包。
- 已删除早期 `ProofOfFandomBadge` ERC-1155 SBT 原型，改用 Gateway、ERC-721 会员身份和 ERC-1155 纪念资产三个独立合约。
- 本周 Mini Demo 不接入 Discord、Telegram、X 等真实社区数据，先使用 3–5 组模拟数据验证画像的易懂性和价值。
- 暂不开发多社区创建与切换、按社区拆分的 FAN / 等级 / Badge / 排行榜、多链与跨链身份聚合。
- 暂不开发 NFT 拍卖、链上二级市场、版税、DAO、协议代币和真实空投。
- 暂不让 AI 自动改分、自动授权、自动设定资产参数或直接发送合约交易。
- 暂不进行 Monad 主网部署；不建设复杂微服务、大规模运维和完整管理后台。

## AI 帮助完成了什么：

- 将初始项目想法拆分为 PRD、技术架构、MVP 路线、模块边界和可验收的需求项。
- 协助讨论并收窄 LangGraph / AI Agent 的职责范围，补充权限、密钥、奖励和链上操作边界。
- 协助设计钱包登录、统一用户、主钱包、会费验证、FAN 流水、终身等级和链上资产的数据与接口方案。
- 辅助完成 FastAPI / LangGraph 模板改造、前端 Fanora 页面与真实 API 接入、合约与 Monad / Pinata 适配、数据库迁移以及测试用例补充。
- 辅助实现粉丝画像、Quest 内容审核、任务推荐和 NFT metadata / 图片草案等 AI 工作流，并为模型不可用时保留规则降级。
- 协助检查代码问题、补充 lint、类型、单元测试和构建验证，并整理 README、交付总结、演示指南和 LangGraph 实现说明。
- AI 提供分析、代码草案和文档整理；最终的产品方向、功能取舍、环境配置、链上操作、测试执行和验收结论由团队成员确认。

## 团队进行了哪些检查或修改：

- 前端已进行 TypeScript 类型检查、ESLint、已配置测试、生产构建和主要页面人工冒烟测试；生产构建通过，仍有 4 条 Hook / 图片优化 warning。
- 后端已进行 Ruff、Pyright、Pytest、数据库迁移和核心 API 检查；当前核心专项测试 21 项通过，全量测试仍受缺失种子图片影响。
- 三个合约已经过 19 项 Hardhat 测试，检查动态会费、SBT 不可转让、供应量、单钱包上限、时间窗口、claimKey、暂停和 metadata 冻结等规则。
- 已人工验证前后端可启动、首页与 NFT 广场可正常渲染，并复核 Monad Testnet 的合约地址、ABI、部署交易和前后端配置同步。
- 已根据安全边界删除私钥导出和旧登录链路，并增加一次性挑战、签名恢复、限流、幂等键和交易状态记录。
- 修改了 FAN 等级算法，将等级判定从当前余额改为终身累计值，避免用户消费后等级倒退。

## 当前遇到的问题：

1. 新环境的后端测试种子数据依赖被 Git 忽略的 `resources/` 图片，缺少指定素材时会出现 `FileNotFoundError`，导致部分全量测试无法完成。
2. 链上写入主要仍在 HTTP 请求中等待确认，尚缺少可靠后台队列、自动重试、链重组处理、常驻事件监听和完整对账。
3. 任务限定 Badge 和演唱会纪念卡尚未完成资格领取、运营创建和前端闭环。
4. NFT 发布与购买的失败补偿、退款、下架、内容治理和管理员界面尚未完成。
5. NFT 原始图片仍可以 Base64 形式保存在 PostgreSQL，生产环境需迁移到独立对象存储并补充配额、扫描与清理策略。
6. Testnet 的运营权限尚未拆分为最小权限账户，管理员权限未迁移至多签。
7. 部分首页图片仍有宽高比例和 LCP 优化提示。旧的“后台创建钱包”文案已在本轮体验改进中清理。

## 下一步准备做什么：

1. 修复新环境的种子图片依赖，为缺失素材提供已提交资源或确定性回退，恢复后端全量测试。
2. 建立可靠任务队列和独立 Worker，为链上操作增加重试、重放、事件监听、链重组策略和数据库 / 链上差异报告。
3. 补齐 `CONCERT_CARD` 与 `TASK_LIMITED_BADGE` 的创建、资格验证、领取和前端展示闭环。
4. 完成 NFT 的编辑、下架、失败补偿、退款、内容治理和管理员操作页。
5. 将原始上传媒体迁移到独立对象存储，完成运营账户权限拆分、密钥托管、告警和管理员多签。
6. 邀请至少 3 名体验者试用粉丝画像 Mini Demo，重点记录“是否易懂、是否可信、是否能帮助识别核心粉丝”，再根据反馈调整画像规则和演示范围。
