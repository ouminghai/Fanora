# Mini Demo Technical Scope

## 本周最需要完成的核心功能是什么？

本周只完成一个核心功能：

> **将一名模拟社区成员的互动数据转换成一张可解释的粉丝画像卡片。**

用户输入或选择以下数据：

- Fan Token 数量；
- 已完成任务数；
- 活跃天数；
- 邀请人数；
- 链上互动次数。

系统返回并展示：

- 综合评分；
- 活跃度、忠诚度、影响力和贡献度分数；
- 粉丝类型与标签；
- 一段简短的判断理由；
- Badge 建议稿（满足规则时显示，但不实际铸造）。

本周最重要的不是增加更多功能，而是确保体验者能在 3 分钟内完成输入、看到结果，并理解画像的判断依据。

## 可以复用哪些现有工具、合约、SDK 或代码？

### 前端

- 复用现有 **Next.js 15、React 19 和 TypeScript** 项目，不建立新的前端工程。
- 复用现有 Axios API Client，调用后端分析接口。
- 复用 Bootstrap、Lucide React 和现有 Fanora 页面样式，快速完成输入表单和画像卡片。
- 复用 `frontend/public/img/badges/` 中已有的等级图片作为 Demo 视觉素材。
- 复用 `frontend/data/fanora.ts` 中的展示数据和文案结构，减少重复整理。

### 后端与 Agent

- 直接复用 FastAPI 接口：`POST /api/v1/agent/fan-profile/analyze`。
- 复用现有 `FanProfileRequest` 和 `FanProfileAnalysis` 数据结构进行输入校验与结果输出。
- 复用现有 LangGraph 粉丝画像流程，包括评分、分类、标签、风险等级和 Badge 草案生成。
- 复用已经存在的确定性规则 fallback；即使没有配置模型 API，Demo 也能稳定运行。
- 复用现有接口测试作为最基础的验收依据。

### 合约与 Web3 SDK

- 仓库已有 Monad Testnet 部署记录，以及 Membership Gateway、Membership Identity 和 Collectibles 三个合约。
- 已有 RainbowKit、wagmi 和 viem，可以在后续需要钱包连接和链上读取时复用。
- 本周 Demo 不需要调用这些合约，也不需要连接真实钱包。它们只作为后续验证链上身份能力的现有基础，不进入本周核心流程。

## 哪些功能暂时无法完成，需要简化或使用 Mock？

| 功能 | 本周处理方式 | 原因 |
| --- | --- | --- |
| Discord、Telegram、X 等社区数据采集 | 使用 3–5 组预设成员数据 Mock | 真实平台接入需要授权、数据清洗和隐私处理 |
| 真实链上行为聚合 | 手动输入或使用预设的链上互动次数 | 多链索引和行为归类超出本周范围 |
| AI 自由分析 | 优先使用现有规则；模型输出作为可选增强 | 避免模型配置、费用或不稳定性阻塞演示 |
| 粉丝 Badge 铸造 | 只展示 Badge 建议稿和图片，不发送交易 | 本周验证的是画像价值，不是资产发行流程 |
| 钱包登录 | 使用固定的演示钱包地址 | 避免增加签名、网络切换和钱包兼容问题 |
| 自动发放积分或奖励 | 只展示建议，不修改任何真实账户数据 | 自动执行涉及权限、安全和业务规则验证 |
| 完整社区后台 | 只制作单页输入与结果展示 | 保证本周可以完成、演示和收集反馈 |
| 画像长期存储与历史对比 | 本周可不展示，必要时只保存当前结果 | 历史趋势不是核心假设所必需的功能 |

## 本周 Demo 的最小闭环

1. 打开 Mini Demo 页面。
2. 选择一组模拟粉丝数据，或手动填写数据。
3. 点击“生成粉丝画像”。
4. 前端调用已有分析接口。
5. 页面展示评分、类型、标签、解释和 Badge 建议稿。
6. 邀请体验者回答：结果是否容易理解，是否有助于识别核心粉丝？

只要这个闭环可以稳定展示，本周目标即视为完成。真实平台接入、钱包连接和链上铸造均不作为本周验收条件。
