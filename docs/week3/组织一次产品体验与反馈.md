# 组织一次产品体验与反馈

> 项目：Fanora Protocol  
> 记录日期：2026-07-23  
> 当前状态：已完成项目介绍、Demo 流程和测试邀请材料；待实际发送给至少 3 名团队外同学并补充真实反馈。

## 分享方式：

- 由项目发起人在学员微信群发布 Fanora 项目介绍、GitHub 仓库和 Demo 截图 / 录屏，公开邀请团队外同学参加体验。
- 同时私聊邀请至少 3 名同学，优先覆盖一名熟悉 Web3 的用户、一名不熟悉 Web3 的用户和一名有社区运营经验的用户。
- 体验可通过线上屏幕共享或现场演示进行，预计每人 15–20 分钟。体验使用 Monad Testnet 或模拟数据，不要求用户提供私钥、助记词或购买真实资产。
- 如钱包、Pinata 或链上环境不稳定，则改用预先准备的演示账号、录屏和粉丝画像 Mini Demo，保证参与者仍能理解核心流程。

### 邀请文案

> 你好！我们正在测试 Fanora 的首个可体验版本。Fanora 是一个 Web3 粉丝社区，用户的签到、创作、任务和社区互动会形成 FAN 成长积分、会员等级和可验证的数字收藏。想邀请你用 15–20 分钟体验 Demo，帮我们看看功能是否容易理解、哪一步最容易犹豫，以及哪种奖励最能让你感到参与被记录。测试使用 Monad 测试网或模拟数据，不涉及真实资产，也不会索取私钥或助记词。如果愿意参加，请回复“参加测试 + 方便的时间”，谢谢！

## 分享了什么：

- Fanora 的核心问题：粉丝贡献分散在签到、内容互动、活动和链上行为中，社区运营者难以快速、公平地识别核心粉丝。
- Fanora 的解决方案：将粉丝互动记录转化为 FAN、终身成长等级、AI 粉丝画像、链上会员身份和数字收藏品。
- 项目 Demo 的主要流程：连接钱包并签名登录 → 加入官方社区 → 签到或完成任务 → 获得 FAN 和等级成长 → 查看粉丝画像、会员身份或数字收藏。
- Mini Demo 的核心流程：选择或输入一组模拟社区数据，由系统生成综合评分、分项评分、粉丝类型、贡献标签、判断理由和 Badge 建议稿。
- 项目的安全边界：Fanora 不读取或保存用户私钥；登录签名不会转移资产；AI 不直接修改积分、权限或合约状态。
- 当前已完成的网页、演示指南、Monad Testnet 合约地址、GitHub 仓库以及部分仍在开发的功能和已知问题。

## 团队准备改进什么：

以下是演示前检查发现的改进方向，不代表已收到的用户反馈。实际测试后将根据至少 3 名体验者的重复意见重新排序：

1. 简化首次体验路径，让新用户能在 3 分钟内完成“输入数据 → 生成画像 → 理解结果”，不被钱包或链上配置阻塞。
2. 在粉丝画像中增加更明确的“评分依据”和“为什么是这个粉丝类型”说明，提高可解释性和可信度。
3. 已清理首页旧的“邮箱或社交账号创建钱包”文案，统一为 RainbowKit 直连用户自有钱包，并增加“登录签名不消耗 Gas、不授权资产转移”的提示。
4. 加强任务完成后的反馈，将 FAN 变化、等级进度、审核结论和纪念品状态放在更容易发现的位置。
5. 优先修复新环境的种子图片依赖和后端全量测试，减少体验过程中因本地素材缺失导致的失败。
6. 完成链上后台重试与对账、任务 Badge 领取和 NFT 失败补偿，并为等待中、失败和缺少配置状态提供清晰的用户说明。

## 体验完成标准

- 实际向至少 3 名团队外同学发送邀请，并保留群消息、私聊、线上会议或体验记录中的一种证据。
- 至少 3 名体验者完成核心 Demo 或观看完整录屏。
- 补充至少 3 份真实反馈，不记录私钥、助记词、密码或其他敏感信息。
- 对重复出现的意见进行归类，最终确认 1–3 项下一阶段优先改进内容。
