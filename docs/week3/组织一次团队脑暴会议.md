# 组织一次团队脑暴会议

## 会议基本信息

**会议时间：** 2026 年 7 月 23 日，预计 30–45 分钟；当前先完成个人预演，正式组队后再与成员共同补充和确认。

**参与成员：**

- 发起人：产品与技术负责人，负责主持、记录和整理候选方向。
- 其他成员：目前待招募，加入后需要各自提出至少一个想法，并共同确认最终方向。

> 说明：当前尚未确认其他团队成员，因此本文不虚构成员观点。以下内容是发起人用于正式会议的初始想法和筛选记录。

## 会议目标

在 30–45 分钟内明确：

1. 团队想帮助哪类用户；
2. 用户遇到了什么具体问题；
3. 哪个问题最值得优先验证；
4. 哪个方向能在本周形成可以展示的 Mini Demo。

本次讨论不追求功能最多或技术最复杂，而是选择一个问题清楚、团队能够完成、体验者容易理解的最小方向。

## 每位成员提出的想法

### 发起人：产品与技术负责人

#### 想法一：可解释的粉丝画像卡片

- **目标用户：** 早期 Web3 创作者、项目社区负责人和社区运营人员。
- **核心问题：** 粉丝贡献散落在任务、活跃、邀请和链上互动等场景中，运营人员难以快速、公平地识别核心粉丝。
- **解决方式：** 输入一组成员互动数据，生成综合评分、粉丝类型、贡献标签和判断理由，并以画像卡片展示。

#### 想法二：社区任务与积分看板

- **目标用户：** 需要组织粉丝活动的社区运营人员和社区成员。
- **核心问题：** 社区任务发布、完成状态和积分记录分散，成员不清楚下一步可以参与什么。
- **解决方式：** 用一个简单看板展示任务、奖励、参与状态和积分变化。

#### 想法三：链上会员身份 Badge

- **目标用户：** 希望给核心粉丝提供身份认证的创作者社区。
- **核心问题：** 传统平台身份无法由用户持有，也难以跨平台证明。
- **解决方式：** 根据粉丝等级生成 Badge，并在测试网上铸造不可转让的会员身份。

#### 想法四：粉丝数字纪念品展示页

- **目标用户：** 参与演唱会、线上活动或社区共创的粉丝。
- **核心问题：** 粉丝参与过的活动缺少统一、长期的数字纪念记录。
- **解决方式：** 用收藏页面展示用户获得的活动纪念品和社区 Badge。

### 筛选结论

- “可解释的粉丝画像”直接对应社区运营人员识别核心粉丝的问题，用户和使用场景较清楚。
- 仓库已经具备评分规则、粉丝分类、FastAPI 分析接口和前端基础，可以在本周形成稳定演示。
- 该方向不依赖真实社区平台授权、真实钱包或链上交易，可以通过模拟数据完成闭环。
- Demo 结果容易向体验者展示，也方便继续询问“结果是否可信、是否容易理解、是否有助于运营决策”。

## 最终选择的方向

**根据模拟的社区互动数据生成一张可解释的粉丝画像卡片。**

Mini Demo 的最小流程为：

1. 选择一组模拟成员数据或手动填写数据；
2. 点击“生成粉丝画像”；
3. 系统生成综合评分、分项评分、粉丝类型、标签和判断理由；
4. 页面展示画像卡片和 Badge 建议稿，但不执行链上铸造；
5. 邀请体验者判断结果是否清楚、可信并能帮助识别核心粉丝。

## 选择它的原因

- **问题相对真实：** 社区运营人员目前经常依靠表格、聊天记录和个人印象识别活跃成员。
- **已有基础可复用：** Fanora 已有前端工程、后端分析接口、评分分类规则和 Badge 素材。
- **本周能够完成：** 只需形成输入、分析和结果展示的单页闭环，不依赖外部平台接入。
- **便于用户测试：** 体验者可以在 3 分钟内走完流程并给出明确反馈。
- **安全风险较低：** 不需要真实私钥、助记词、主网资产或生产环境权限。

## 暂时放弃的想法

### 社区任务与积分看板

暂不作为本周主方向。它涉及任务发布、完成验证、积分规则和成员权限，范围比单一画像功能更大。后续可作为画像数据的来源继续验证。

### 链上会员身份 Badge

暂不进行真实铸造。钱包连接、网络切换、交易确认和合约权限会增加演示的不确定性。本周只展示 Badge 建议稿或 Mock 图片。

### 粉丝数字纪念品展示页

暂不作为核心验证方向。展示页面容易完成，但无法直接验证社区运营人员最重要的识别问题，可在后续作为粉丝画像的展示延伸。

### 真实社区数据自动采集

暂不接入 Discord、Telegram、X 或其他平台。真实接入需要平台授权、隐私确认、数据清洗和稳定性处理，本周使用 3–5 组预设数据替代。

## 安全约定

- 不在会议、群聊、文档或代码仓库中共享私钥、助记词和账户密码。
- Demo 使用模拟数据、测试地址和测试环境，不要求体验者连接真实钱包。
- API Key、数据库密码和其他敏感配置不得写入公开文档或提交到代码仓库。
- 如果后续进行链上测试，必须再次确认网络、合约地址、钱包权限和交易内容。

## 待正式团队确认

新成员加入后，需要在一次 30–45 分钟的正式会议中完成以下事项：

- 补充每位成员提出的原创想法；
- 重新确认候选方向评分；
- 通过讨论或投票确认最终方向；
- 根据成员实际专长重新分配负责人；
- 在任务看板中记录任务和完成时间。
