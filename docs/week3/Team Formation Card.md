# Team Formation Card

## 团队名称

**Fanora Builders（暂定）**

## 团队成员与角色

| 成员 | 角色 | 主要职责 |
| --- | --- | --- |
| 我 | 发起人 / 产品与技术负责人 | 推进项目、拆分任务、负责全栈开发并整合阶段成果 |
| 待招募成员 | 记录与协作负责人 | 记录会议结论、维护任务看板、跟进任务状态 |
| 待招募成员 | 用户研究 / 设计 / 运营 | 验证用户需求、优化产品体验、组织社区测试 |

目前尚未确认其他成员，现公开招募 1–4 名对 AI、Web3、链上身份或创作者经济感兴趣的伙伴。

## 共同关注的问题

如何利用 AI Agent 和区块链技术，帮助粉丝沉淀可验证的身份与贡献记录，并帮助创作者社区更高效地完成用户激励、会员管理和长期互动。

团队计划围绕 **Fanora** 共同完成一个可以实际演示和验证的 MVP，并通过真实用户反馈持续调整产品方向。

## 目前缺少的角色

- **产品运营 / 用户研究：** 访谈目标用户，验证需求与使用场景。
- **UI/UX 设计：** 优化产品交互、视觉呈现和演示体验。
- **社区增长：** 寻找早期用户，组织产品测试并收集反馈。
- **Web3 / 合约安全：** 协助检查链上机制、权限设计与合约风险。

## 基础协作方式

### 群聊与任务看板

- 组队完成后建立微信群或 Telegram 群，用于日常沟通和进度同步。
- 使用 GitHub Projects 或 Notion 建立任务看板。
- 看板分为“待处理”“进行中”“待验证”“已完成”四个状态。
- 每项任务必须明确负责人、目标和预计完成时间。

### 每周同步时间

暂定每周日晚上 **20:00** 进行一次团队同步，集中讨论：

1. 本周已经完成的工作；
2. 当前遇到的问题与风险；
3. 下周目标和任务负责人。

具体时间将在团队成员确认后共同调整。

### 任务分配与决策方式

- 根据成员的兴趣和专长自愿认领任务。
- 每项任务设置一名主要负责人，其他成员可以协作支持。
- 团队先通过讨论尽量达成共识。
- 无法达成一致时，由对应任务负责人提出建议，项目推进负责人结合 MVP 目标作最终取舍。
- 每次同步指定一名成员记录结论、任务负责人和截止时间。

## 安全边界

- 不共享私钥、助记词、钱包备份或个人账户密码。
- 不在群聊、文档和代码仓库中公开 API Key、数据库密码或生产环境密钥。
- 开发和演示阶段优先使用测试网、独立测试钱包与最小金额。
- 所有敏感配置通过本地环境变量或安全的密钥管理工具保存。
- 涉及合约部署、资产转移或权限调整时，必须由相关成员再次核对目标网络、地址和操作内容。
