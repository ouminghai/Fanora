# 根据反馈改进项目

> 项目：Fanora Protocol  
> 完成日期：2026-07-23

## 收到的反馈：

在准备对外分享材料和检查首次体验路径时，发现首页“加入流程”的介绍与当前产品实现不一致：

- 页面写着“使用邮箱或社交账号快速加入，系统会在后台创建并绑定 Web3 钱包”，容易让体验者误以为 Fanora 会创建、托管或接触用户钱包密钥。
- 页面写着“LangGraph Agent 持续更新 Fan Token”，容易让用户误以为 AI 可以直接改变积分余额。
- “解锁链上 Badge”未说清 ERC-721 会员身份与 ERC-1155 任务纪念品的区别。

这些问题已在项目交付总结和体验准备文档中被记录。截至本次修改，尚未收到可核对的外部体验者反馈；本轮先对已经确认会造成误解的问题进行改进。

## 完成的改进：

1. 将首页第一步从“加入 Fans Club”改为“连接自有钱包”，明确用户通过 RainbowKit 连接 MetaMask、WalletConnect 等已有钱包。
2. 将底部安全说明改为：用户始终使用自己的钱包；登录签名不消耗 Gas、不授权资产转移；Fanora 不读取或保存私钥与助记词。
3. 将 FAN 的来源说清为“任务通过服务端规则验证后发放”，同时明确 Agent 只负责画像分析和解释，不直接修改余额。
4. 将第四步改为“沉淀链上身份”，区分由终身 FAN 推动的 ERC-721 会员身份和使用 ERC-1155 记录的任务纪念品。
5. 增加首页钱包文案回归测试，防止“后台创建钱包”或“Agent 修改 FAN”等旧说法再次出现。

本次改动涉及：

- `frontend/data/fanora.ts`
- `frontend/components/homes/common/Process.tsx`
- `frontend/tests/wallet-login-routing.test.ts`

验证结果：

- 钱包登录专项测试：4 项全部通过。
- TypeScript 类型检查：通过。
- 本次修改文件的 ESLint 检查：通过。

## 修改前后对比：

| 范围 | 修改前 | 修改后 |
| --- | --- | --- |
| 进入方式 | 邮箱或社交账号加入，系统在后台创建钱包 | 用户通过 RainbowKit 连接自有钱包，完成一次无 Gas 登录签名 |
| 钱包所有权 | 暗示 Fanora 会创建或管理用户钱包 | 明确钱包由用户管理，Fanora 不读取、保存私钥或助记词 |
| FAN 发放 | 文案暗示 LangGraph Agent 会持续更新 FAN | 明确 FAN 由服务端确定性规则发放，Agent 不直接修改余额 |
| 链上资产 | 统一称为“链上 Badge” | 分清 ERC-721 会员身份和 ERC-1155 任务纪念品 |
| 风险提示 | 未在加入流程中清晰说明签名权限 | 明确登录签名不消耗 Gas，也不会授权资产转移 |

## 目前还有的问题：

1. 尚未完成至少 3 名团队外体验者的实际测试，因此还需确认新文案是否真正降低了钱包与 AI 权限的理解成本。
2. 首页部分图片仍有宽高比例和 LCP 优化 warning。
3. 链上写入缺少可靠后台队列、自动重试、链重组处理和完整对账，等待时间较长时的用户反馈仍需改进。
4. 任务限定 Badge 和演唱会纪念卡的领取与前端展示闭环尚未完成。
5. 新环境的后端全量测试仍受缺失种子图片影响。
6. 实际用户反馈收集完成后，还需根据重复出现的问题确定下一轮 1–3 项优先改进内容。
