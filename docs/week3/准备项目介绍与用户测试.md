# Fanora 项目介绍与用户测试准备

> 适用场景：Week 3 项目展示、招募首轮体验用户、组织 15–20 分钟可用性测试  
> 测试版本：Fanora MVP（Monad Testnet）  
> 核心测试对象：对 Web3 有基础了解，或愿意在引导下使用测试钱包的粉丝用户

## 一句话项目介绍

Fanora 是一个把粉丝的真实互动沉淀为 FAN、成长等级和链上会员纪念的 Web3 粉丝社区。

## 100–200 字项目简介

Fanora 希望让粉丝的签到、创作、评论和活动参与不再只是转瞬即逝的数据。用户连接钱包后，可以在官方社区完成任务、获得站内 FAN、提升会员等级，并把长期贡献记录为可验证的链上会员身份和数字收藏品。创作者也能用任务与限量纪念品持续回馈核心粉丝。当前版本运行在 Monad 测试网，重点验证从参与互动到获得身份与收藏的完整体验；测试资产不具备真实货币价值。

## 给新人的概念说明

- **钱包**：可以理解为用户在 Web3 应用中的账号。Fanora 只请求登录签名，不会读取私钥或助记词。
- **登录签名**：用于证明“这个钱包属于你”，不消耗 Gas，也不会授权 Fanora 转走资产。
- **Monad 测试网**：供开发和体验使用的区块链测试环境，其中的测试 MON 和测试资产没有真实货币价值。
- **FAN**：Fanora 内部的粉丝成长积分，可通过签到、发帖和互动等行为获得；目前不是可交易的加密货币。
- **链上会员身份**：记录正式会员身份与等级的不可转让数字会员证。
- **数字收藏品**：由社区或粉丝发布的限量纪念资产，可在个人收藏页查看。

### 标题

来体验 Fanora：让每一次粉丝互动都成为可收藏的成长记录

### 正文

你好！我们正在测试 Fanora 的首个可体验版本。

Fanora 是一个 Web3 粉丝社区：你可以连接测试钱包、参与签到或社区任务、获得 FAN 成长积分，并查看自己的会员等级与数字收藏。

我们想邀请你完成一次约 15–20 分钟的体验。不需要购买任何真实资产，也不要求你熟悉区块链；测试过程使用 Monad 测试网，所有测试资产均无真实货币价值。我们主要想了解：第一次使用时是否容易理解、操作中哪里会犹豫，以及哪些反馈最能让你感到“我的参与被记录了”。

测试过程中请尽量说出你正在想什么。这里没有正确答案，我们测试的是产品，不是你。

- 测试方式：现场观察或线上屏幕共享

- 隐私提醒：请勿向任何人展示或发送私钥、助记词；测试人员也不会向你索取

如果你愿意参加，请回复“参加测试 + 方便的时间”，感谢你帮助我们把 Fanora 做得更容易使用。

## 用户测试任务

### 场景

你刚刚了解到 Fanora，希望加入社区，并通过一次实际互动确认自己的参与会得到怎样的记录和回馈。

### 任务指令（直接念给用户）

> 请从 Fanora 首页开始，在不查看操作教程的情况下连接测试钱包并完成登录；随后找到官方社区，完成一次签到或任意一个当前可完成的粉丝任务；最后找到你的 FAN 余额、会员等级或任务奖励记录，并向我们说明这次互动给你带来了什么变化。完成后即可停止。

### 主持人准备

- 启动可用的前端、后端与数据库环境，并提前检查健康状态。
- 准备一个已配置 Monad Testnet 的兼容钱包，钱包中放入少量测试 MON。
- 优先提供已经是正式会员的测试账号，避免链上入会等待干扰本轮核心流程。
- 保留一个全新或当日未签到的账号，确保用户能够获得可观察的 FAN 变化。
- 准备屏幕录制或观察记录表，并在开始前征得用户同意。
- 若真实链路临时不可用，记录失败位置，不代替用户完成；随后可切换至准备好的演示账号继续观察信息理解情况。

### 主持规则

- 除非用户完全无法继续，否则不要告诉用户应该点击哪里。
- 用户停顿时先问“你现在在找什么？”或“你原本期待这里发生什么？”。
- 记录用户首次点击、犹豫位置、误解的文案、钱包弹窗反应和完成时间。
- 不把技术故障归因于用户；如果出现报错，记录页面、操作、时间和钱包地址后四位。

### 完成标准

- 用户能够说明登录签名的用途，并知道它不是付款或资产授权。
- 用户能独立找到官方社区及签到/任务入口。
- 用户成功完成一次互动，或能清楚判断系统为何未完成。
- 用户能找到至少一种结果反馈：FAN 变化、积分流水、任务完成状态或会员成长进度。
- 用户能用自己的话解释 Fanora 的核心价值。

### 建议观察指标

| 指标 | 记录方式 |
| --- | --- |
| 任务完成率 | 独立完成 / 提示后完成 / 未完成 |
| 完成时间 | 从打开首页到找到奖励结果的总时长 |
| 关键路径偏离 | 误点页面、返回次数、重复点击次数 |
| 求助次数 | 用户主动提问或主持人必须介入的次数 |
| 信任障碍 | 对签名、测试 MON、交易或隐私产生疑虑的位置 |
| 价值理解 | 用户能否说明互动、FAN、等级与链上身份之间的关系 |

## 反馈问题

1. 如果要向朋友介绍 Fanora，你会怎么用一句话说明它？
2. 在刚才的过程中，哪一步最让你困惑或不敢继续？为什么？
3. 你是否清楚这次互动获得了什么，以及 FAN、等级和链上会员身份之间有什么关系？
4. 哪一种回馈最能让你愿意继续参与：成长积分、会员等级、限量收藏品、社区认可，还是其他？
5. 如果下周只能改进一个地方，你最希望我们先改什么？

## 项目介绍 Landing Page 草稿

### 页面目标

让第一次接触 Fanora 的用户在 30 秒内理解三件事：这是一个粉丝社区；参与会形成持续的成长记录；用户可以安全地用钱包进入测试体验。

### 页面结构与文案

#### 1. 首屏 Hero

**眉题**  
Your Fandom, Onchain.

**主标题**  
让每一次热爱，都成为可证明的粉丝身份

**副标题**  
在 Fanora 参与社区、完成任务并获得 FAN。你的长期互动将积累为会员等级、链上身份和独一无二的粉丝收藏。

**主要按钮**  
连接钱包，开始体验

**次要按钮**  
先看看如何成长

**安全提示**  
登录签名不消耗 Gas，也不会授权资产转移。当前为 Monad 测试网体验，测试资产无真实货币价值。

**视觉建议**  
深色星空背景中央放置一张会随等级变化的数字会员卡；周围以“签到、创作、任务、收藏”四条发光轨迹汇入会员卡，直观表达“互动沉淀为身份”。

#### 2. 为什么需要 Fanora

**标题**  
你的支持，不该散落在一次次点赞里

**正文**  
传统平台上的互动很容易被时间线淹没，也很难证明一位粉丝长期投入了什么。Fanora 把经过验证的社区参与汇总成连续的成长记录，让粉丝看见自己的历程，也让创作者更好地识别和回馈真正的支持者。

#### 3. 三步说明核心流程

| 步骤 | 标题 | 说明 |
| --- | --- | --- |
| 01 | 连接你的钱包 | 用钱包签名登录，建立由你掌握的 Fanora 身份。 |
| 02 | 参与真实互动 | 签到、创作、评论或完成社区任务，获得 FAN。 |
| 03 | 解锁成长与收藏 | 提升会员等级，生成链上会员证，并收藏限量粉丝纪念品。 |

#### 4. 核心价值卡片

**参与有回音**  
每次符合规则的互动都会获得清晰结果，不再只是一个转瞬即逝的数字。

**成长看得见**  
FAN、终身累计和等级进度共同呈现你与社区长期同行的轨迹。

**身份可验证**  
会员身份和数字收藏记录在链上，由钱包持有，可通过区块浏览器验证。

**创作者能回馈**  
创作者可以通过任务、会员权益和限量纪念品连接真正活跃的核心粉丝。

#### 5. 产品预览区

**标题**  
从一次互动，到一份长期身份

**展示内容**

- 官方社区：浏览动态、签到、创作和参与讨论。
- 任务中心：查看奖励与要求，完成可验证的粉丝任务。
- 成长面板：查看可用 FAN、终身 FAN、等级和下一等级进度。
- 我的收藏：管理链上会员证与获得的粉丝数字收藏品。

**视觉建议**  
用四张连续的产品截图组成横向故事：社区签到 → 获得 FAN → 等级提升 → 会员证/收藏品出现。每张图只标注一个关键动作，避免一次展示过多 Web3 信息。

#### 6. 信任与安全说明

**标题**  
钱包由你掌握，记录由链上验证

- Fanora 不生成、不索取、也不保存用户的私钥或助记词。
- 登录签名只用于验证钱包归属，不等于付款或资产授权。
- 涉及测试网交易时，钱包会单独显示确认请求。
- 当前体验使用 Monad Testnet，测试 MON、FAN 与测试 NFT 均不代表真实投资价值。

**正文**
