# Fanora MVP 路线图

> 版本：v1.6\
> 更新日期：2026-07-23\
> 需求基线：[PRODUCT_REQUIREMENTS.md](./PRODUCT_REQUIREMENTS.md)\
> 架构基线：[ARCHITECTURE.md](./ARCHITECTURE.md)

## 1. 路线原则

- PostgreSQL 保存用户、任务、FAN、终身等级、NFT 市场和链上操作的业务事实。
- ERC-721 会员身份与 ERC-1155 纪念资产分开实现、测试和部署。
- 图片和 metadata 成功固定到 Pinata 后才提交链上写入。
- Agent 不修改 FAN、等级、权限、发布资格或合约参数。
- 页面展示、文档完成或单次交易成功不能替代幂等、失败恢复和对账验收。

## 2. 当前基线

### 已完成

- RainbowKit 直连钱包、一次性 challenge、签名验证、统一用户与会话。
- 动态会费 Gateway、链上付款验证、正式会员激活、管理员改价与提现。
- 单一官方社区、创作、回复、点赞、收藏、签到、任务和幂等 FAN 流水。
- 可用 FAN 与终身累计 FAN 分离；消费不降低已经获得的会员等级。
- LangGraph 画像、确定性降级、结构化输出和运行记录。
- ERC-721 SBT 会员身份、会员证生成/刷新、等级 metadata 和 Pinata 固定。
- ERC-1155 合约、粉丝限量 NFT 发布、FAN 购买、点赞/收藏、创作者集合和个人收藏。
- Gateway、MembershipIdentity、Collectibles 已部署 Monad Testnet；ABI 和地址已同步至前后端。
- 合约测试 19 项通过；前端可实际加载 NFT 市场并完成分类筛选。

### 当前缺口

- 后台队列、失败自动重试、链重组处理、常驻事件监听和数据库/链上完整对账。
- 任务限定 Badge 与演唱会纪念卡的资格领取、运营创建和前端闭环。
- 多钱包关联、主钱包切换以及不可转让身份的恢复/迁移策略。
- 粉丝 NFT 编辑、下架、失败补偿、退款、内容治理和管理员操作页面。
- 原始上传媒体从 PostgreSQL/Base64 迁移到独立对象存储，并补齐配额、扫描和清理。
- Testnet 运营角色拆分、密钥托管、告警和管理员多签。

## 3. 阶段 A：完成链上可靠性闭环

目标：让当前会员证、NFT 发布和购买不依赖单次 HTTP 请求必然成功。

交付物：

1. 可靠任务队列与独立 Worker。
2. `chain_operations` 自动重试、退避、最终失败和人工重放。
3. 会员身份、会员证、NFT token type 与 mint 事件的常驻监听。
4. 链重组确认策略和数据库/链上差异报告。
5. 发布费、购买扣款与铸造失败时的补偿或恢复策略。

退出条件：

- 重放同一 operationId/claimKey 不会重复铸造或重复扣 FAN。
- HTTP 超时后仍可从 operation 状态恢复最终结果。
- 链上事件可重建关键数据库状态，并能发现差异。

## 4. 阶段 B：补齐任务纪念资产

目标：把当前站内任务与 ERC-1155 奖励真正连接起来。

交付物：

1. `CONCERT_CARD` 与 `TASK_LIMITED_BADGE` 类型创建和管理流程。
2. 任务完成、名单或链上凭证驱动的领取资格。
3. claimKey、最大供应量、单钱包上限和领取时间窗的端到端校验。
4. 前端任务卡、领取进度、失败提示和个人收藏展示。

退出条件：

- 超发、重复领取、过期领取和任意铸造地址均被拒绝。
- 任务记录、FAN 流水、收藏记录和链上事件可互相追踪。

## 5. 阶段 C：生产化媒体与 NFT 市场治理

目标：将当前可演示的粉丝 NFT 市场提升为可长期运行的服务。

交付物：

1. 原始图片迁移到对象存储，数据库只保存对象键、哈希和媒体元数据。
2. MIME/文件签名/尺寸校验之外的恶意内容扫描、用户配额和清理策略。
3. NFT 编辑版本、下架、失败补偿、退款或争议处理规则。
4. 创作者和管理员的审计视图，不让 Agent 直接批准或执行链上操作。
5. Pinata pin 状态巡检、重新固定和 Gateway 可用性监控。

退出条件：

- 大文件和恶意文件不能拖垮 API 或数据库。
- 每次发布、购买、扣款、铸造、失败和补偿都有可追踪记录。

## 6. 阶段 D：身份与运营安全

目标：完成钱包生命周期和生产权限治理。

交付物：

1. 多钱包关联与重新认证。
2. 主钱包切换的高风险确认和 SBT/不可转让资产提示。
3. 运营角色拆分、独立密钥或安全签名服务。
4. `DEFAULT_ADMIN_ROLE` 迁移至多签。
5. 指标、日志、告警、备份与灾难恢复演练。

退出条件：

- 任一运营密钥泄露不会同时拥有全部合约权限。
- 钱包变更不会静默丢失或错误迁移不可转让身份。

## 7. 发布验收

1. 前端类型检查、Lint、专项测试和生产构建通过。
2. 后端 Ruff、Pyright、Pytest 和数据库迁移检查通过。
3. 三个合约编译、19 项测试和 Testnet 配置复核通过。
4. 人工完成钱包登录、动态会费、会员证、NFT 市场筛选、发布、购买和个人收藏冒烟测试。
5. 按 [PRODUCT_REQUIREMENTS.md](./PRODUCT_REQUIREMENTS.md) 的完成定义逐项核销。

## 8. 暂不纳入 MVP

- 多社区创建、社区列表搜索和社区切换。
- 按社区拆分 FAN、任务、等级、Badge 和排行榜。
- 多链和跨链身份聚合。
- 将完整积分、任务或粉丝画像写入链上。
- NFT 拍卖、链上二级市场、版税和跨平台交易聚合。
- DAO、协议代币和真实空投。
- AI 自动改分、自动审批或直接控制合约。
- 未经安全评估的 Monad 主网部署。
