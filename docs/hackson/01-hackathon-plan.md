# 推进计划

## 阶段 1：统一目标与 demo 主线

目标：所有人知道要讲什么、演示什么、优先做什么。

产出：

- 完成 `00-goals.md`。
- 明确一句话 pitch。
- 确认 demo 的主用户旅程。
- 列出必须修复的阻塞问题。

检查点：

- 团队成员能用同一套话解释 Fanora。
- 每个功能都能对应到 demo 主线。

## 阶段 2：打磨核心功能

目标：保证 demo 路径能稳定跑通。

优先顺序：

1. 登录和用户身份。
2. 加入社区。
3. 签到或任务领取。
4. FAN 发放和余额更新。
5. 排行榜或个人成长展示。
6. 会员证、NFT 或收藏品展示。

检查点：

- 每个按钮都能产生明确反馈。
- 出错时有可理解提示。
- Demo 数据足够好看、可信、可解释。

## 阶段 3：强化 AI 与 Web3 亮点

目标：让评委看见项目差异化。

重点：

- AI Agent 如何审核互动质量。
- AI Agent 如何生成粉丝画像或推荐任务。
- 链上身份如何承载会员等级。
- NFT 收藏品如何作为贡献或活动证明。

检查点：

- 不夸大未完成能力。
- AI 和链上能力都有对应页面或演示证据。

## 阶段 4：准备演示和提交

目标：把产品、故事和材料收束成可提交版本。

产出：

- 演示脚本。
- 项目 README 更新。
- 提交清单。
- 部署链接。
- 截图或短视频。

检查点：

- 3 分钟版本可以顺畅讲完。
- 5 分钟版本可以展示完整闭环。
- 网络或钱包异常时有备用讲法。
