# 270728 团队会议整理

## 会议基本信息

**会议时间：** 2026 年 7 月 28 日

**会议主题：** 冻结 Hackathon MVP 范围，明确 AI 共创 NFT 闭环、Fan Token 权益逻辑与 Demo 优先级。

**参与成员：**

- 产品与技术负责人：负责梳理 MVP 范围、技术边界、开发顺序与验收标准。
- 团队成员：围绕追星用户付费意愿、AI Agent 定位、Fan Token 权益、移动端体验和 Demo 叙事提出反馈。

> 说明：本文根据团队讨论内容整理，重点记录已形成共识的方向、暂缓事项和下一步开发安排。

## 会议目标

本次会议重点确认：

1. Hackathon 阶段只做一条最小可演示闭环；
2. 明确 AI Agent 在产品中的职责边界；
3. 明确 Fan Token / Badge 与粉丝权益之间的关系；
4. 根据真实粉丝反馈调整产品叙事和 Demo 优先级；
5. 确定接下来五步开发顺序与最终验收标准。

本次讨论不扩展素材后台、多 Creator、多 Agent、二级市场或复杂稀有度系统，优先保证核心链路稳定。

## 一句话 MVP

**粉丝选择官方素材包和视觉风格，通过对话描述自己的故事，消耗 FAN 生成 NFT 草稿，确认后自动发布为 Monad 上的限量 NFT。**

只做这一条闭环。

## 用户完整流程

1. 用户进入“AI 共创 NFT”页面。
2. 选择一个官方素材包。
3. 选择一种视觉风格。
4. Agent 询问用户想表达的故事。
5. 右侧实时整理创作摘要。
6. 用户确认“消耗 10 FAN 生成”。
7. AI 生成 NFT 图片、名称、描述和属性标签。
8. 用户可以修改文字，或再次消耗 FAN 重新生成图片。
9. 用户设置发行量和价格。
10. 用户勾选素材与版权声明。
11. 点击“确认并发布”。
12. 后端自动上传 IPFS、创建 ERC-1155，并显示交易进度和最终链接。

## 页面方案

建议改造现有 `/collections/create` 页面，不改成纯聊天页，而是做成三段式创作工作台。

| 区域 | 内容 | 目的 |
| --- | --- | --- |
| 左侧：创作对话 | Agent 每次只问一个问题，例如想记录哪段粉丝故事、希望表达什么情绪、有什么特别元素必须出现 | 降低创作门槛，引导用户把故事说清楚 |
| 中间：素材与风格 | 官方素材包、视觉风格、配色、可选参考图 | 保证作品有官方视觉边界和版权边界 |
| 右侧：实时 NFT 预览 | 当前图片、名称、描述、属性、发行量、价格、本次消耗 FAN、用户剩余 FAN | 让用户始终知道自己即将生成和发布什么 |

移动端按“选择 → 对话 → 预览确认”的分步流程展示，符合国内追星用户 Mobile First 的使用习惯。

## Agent 职责边界

会议明确：不要让 Agent 负责所有事情。LangGraph 只负责创作部分，确定性业务流程交给后端服务。

### LangGraph 负责

1. 读取用户需求；
2. 检索素材包；
3. 整理创作 Brief；
4. 编排生图 Prompt；
5. 生成名称和描述；
6. 生成图片；
7. 内容与质量检查；
8. 保存草稿。

### 后端服务负责

1. FAN 扣除与退款；
2. 发行量、价格校验；
3. IPFS 上传；
4. ERC-1155 发布；
5. 交易重试与状态记录。

链上发布不放进 Agent 节点。Agent 生成草稿，用户确认后，再由发布服务执行。

## FAN 扣费机制

第一版采用“预扣 → 结算 → 退款”。

| 场景 | 规则 |
| --- | --- |
| 首次体验 | 免费 |
| 后续生成 | 每次生成消耗 10 FAN |
| 重新生成图片 | 再扣 10 FAN |
| 修改名称和描述 | 免费 |
| 每日限制 | 每日最多 3 次 |
| 生成失败 | AI、网络或服务端失败自动退款 |
| 防重复提交 | 相同请求 ID 只能扣费一次 |
| 并发限制 | 同一用户同时只能有一个生成任务 |

## 后端第一版接口方向

尽量扩展现有 NFT Creation Agent，不推翻重写。需要支持以下能力：

1. 获取素材包和视觉风格；
2. 创建创作会话；
3. 保存对话和创作摘要；
4. 确认并发起生成；
5. 查询生成状态；
6. 修改生成结果；
7. 确认并发布；
8. 查询 IPFS 和链上发布进度。

状态统一为：

```text
collecting
→ ready
→ generating
→ draft_ready
→ confirmed
→ uploading
→ publishing
→ published
```

异常进入 `failed`，并记录是否已经退款。

## 素材库第一版

第一版不做素材管理后台，先准备一个固定素材包：**演唱会纪念系列**。

素材包包含：

1. 5–10 张授权图片；
2. Logo 和装饰元素；
3. 官方配色；
4. 禁止使用规则；
5. 三套 Prompt 模板；
6. 三种视觉风格。

素材库的作用不是让 AI 随机挑图片，而是给生成结果统一的官方视觉和版权边界。

## 用户反馈整理

团队成员访谈了几位追星高消费用户，反馈较一致。

| 反馈 | 含义 | 对产品的影响 |
| --- | --- | --- |
| 真正愿意付费的是 Fan Club 权益，而不是 NFT 本身 | 用户更在意优先购票、限定内容、限定周边、见面会资格 | Fan Token / Badge 需要与权益绑定，商业逻辑才更顺 |
| 真正有创作欲的是少数深度粉 | 普通粉丝更偏参与、收藏和消费内容 | AI 创作不面向所有用户，而是服务同人创作者、CP 粉、应援站等深度创作者 |
| 国内追星用户 Mobile First | 国内用户习惯微博超话，日本偏 Fan Club，韩国有打投 App | Web Demo 可以保留，但交互需要按移动端习惯设计 |

## 产品定位共识

### AI Agent 的定位

AI Agent 不是为了所有粉丝都来生成作品，而是服务少数有创作需求的深度粉，帮助他们降低创作门槛。

深度粉可以进一步分为：

- 同人创作者；
- CP 粉；
- 应援站；
- 本来就在持续产出内容的核心粉丝。

普通粉丝更主要的行为是通过 Post、Gallery 购买深度粉创作的有价值 NFT 和纪念品。

### Fan Token 的定位

Fan Token 需要和权益关联。短期 Demo 中可以先假定 Fanora 社区就是官方社区，并在 Quests 和 Community 中增加更多与粉丝权益相关的内容。

可强调的权益包括：

- 优先购票；
- 限定内容；
- 限定周边；
- 见面会资格；
- 官方社区身份；
- 创作权限或高等级发布资格。

### Demo 规则

真实产品中，创作权限可以限制给高等级粉丝，避免社区内容失控。

Hackathon Demo 阶段暂时不做严格等级限制，允许评委和投票用户通过消耗 10 FAN 体验发布 NFT，以保证演示顺畅。

## Web3 叙事共识

本次讨论形成的核心表达：

**把粉丝的爱，变成可验证、带不走的资产。**

Web2 也能做社区、签到和积分，但这些大多是平台数据。一旦平台消失、换平台或账号受限，用户多年积累的身份、贡献和权益都会丢失。

同人创作本来就带有去中心化特征，和 Web3 的去中心化逻辑天然契合。Fanora 的价值不是把所有粉丝行为强行链上化，而是让真正重要的粉丝身份、贡献和纪念资产能够被用户持有和验证。

## 讨论筛选

| 方向 | 当前判断 | 处理方式 |
| --- | --- | --- |
| AI 共创 NFT 闭环 | 最能体现 Web3 x AI Agent，也是 Hackathon 主线 | 本轮优先完成 |
| Fan Token 权益绑定 | 是商业逻辑成立的关键 | 在 Demo 叙事、Quests 和 Community 中强化 |
| 普通粉丝内容消费 | 是社区活跃和商业转化的重要部分 | 保留 Post、Gallery 购买与收藏逻辑 |
| 高等级创作权限 | 真实产品需要，但会增加 Demo 门槛 | Demo 暂缓限制 |
| 素材管理后台 | 不影响主闭环 | 暂不开发 |
| 多 Creator / 多 Agent | 范围过大 | 暂不开发 |
| 二级市场 / 复杂稀有度 | 不影响两分钟演示目标 | 暂不开发 |

## 最终决定

Hackathon 阶段只围绕一条链路开发和演示：

**新用户从选择官方素材包开始，通过 AI Agent 讲述个人粉丝故事，消耗 FAN 生成 NFT 草稿，确认后发布到 Monad，并在 Gallery 中看到作品。**

其他功能只作为背景叙事或后续规划，不抢占主闭环开发资源。

## 风险与约束

- AI 创作链路不能影响发布链路的确定性，发布必须由后端服务控制。
- 扣费必须支持失败退款和请求去重，避免用户重复损失 FAN。
- Demo 暂不做复杂权限，但需要在叙事中说明真实产品会限制高等级粉丝创作。
- 移动端体验需要尽早考虑，不应只做桌面宽屏布局。
- 如果生图或链上发布不稳定，需要准备兜底结果，保证现场演示不被外部服务拖垮。

## 最终验收标准

只看这一件事：

**一个新用户是否能在两分钟内，从选择素材开始，生成一张具有个人故事的 NFT，并在确认后看到它出现在 Gallery 和 Monad 链上。**

如果这条链路没稳定，先不开发素材后台、多 Creator、多 Agent、二级市场或复杂稀有度系统。
